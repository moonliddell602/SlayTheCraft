## 2. V1 详细设计（本轮实施）

### 2.1 数据流

```
引擎(CombatContext) ──► BattleView(纯数据) ──► BattleStatePayload(NBT 编解码) ──► 客户端 ClientBattleState
                                                                                      │
客户端点击 ──► PlayCardPayload(handIndex, enemyIndex) / EndTurnPayload ──► 服务端 CombatManager
```

* **每个参与者收到的是"以自己的视角"生成的快照**：`yourTurn`、自己的手牌/能量/格挡/生命；
  敌人列表与意图是共享的。
* 快照在**开局、出牌、结束回合、战斗结束**时各推一次（不做每 tick 同步）。
* 为什么用一个 NBT 载荷而不是给每个字段写 `StreamCodec.composite`：字段会随 V2–V12 持续增加，
  NBT 方案改动成本低；代价是手工读写，因此**配套一个编解码往返自检**（`BattleViewCheck`）来替代编译期检查。

### 2.2 界面布局（参考杀戮尖塔，位于物品栏位置）

```
┌───────────────────────────────────────────────────────────┐  回合 3 · 你的回合        能量 ③/3
│ 敌人行（V2 会在世界内也显示意图）：                        │  [结束回合]
│   僵尸 HP 20/20  格挡 0  意图 攻击 5 → 你                  │  抽牌堆 4 · 弃牌堆 3 · 消耗 0
│                                                            │
│ 手牌区（屏幕底部，即物品栏位置）：                          │
│   ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐                       │
│   │打击│ │打击│ │格挡│ │重击│ │柄击│  ← 悬停放大 + 费用角标   │
│   └────┘ └────┘ └────┘ └────┘ └────┘                       │
└───────────────────────────────────────────────────────────┘
```

* 卡片暂时仍是**程序化绘制**（圆角面板 + 品质/类型配色 + 名称 + 费用 + 描述），
  与设计文档 §8.5 一致；替换成卡面贴图时只改渲染层。
* 需要指定目标的牌：点击后进入**选目标模式**（敌人高亮），再点敌人即出牌；右键/ESC 取消。
* 界面**不暂停游戏**（`isPauseScreen = false`），并且玩家可以在自己回合内按 ESC 收起界面去看世界
  （收起到本回合结束前不再自动弹出，避免"关不掉"的烦人体验）。
* 非自己回合不显示出牌界面，只保留行动栏摘要。

## 4. 我对模糊点的解读（请确认或纠正）

1. **"更名：防御→格挡"**：把**卡牌「防御」的显示名改为「格挡」**，与已有的"格挡"数值统一（《杀戮尖塔》中文习惯）。
   效果数值不变（1 费获得 5 点格挡）。
2. **"灼烧/凋零"**：两者机制相同（下回合开始按层数掉血），只是来源/命名不同，因此**实现为同一机制的两个名字**
   （`BURN` 与 `DECAY` 两个效果类型，数值逻辑共用）。若你要它们行为不同（例如凋零无视格挡），告诉我。
3. **易伤（vulnerable）** 你没提：**保留现有 ×1.5** 不动。若一并删除请说明。
4. **"保留"关键字**与"回合结束弃手牌"冲突：带保留的牌回合结束**留在手牌**，其余牌照常弃。
5. **"固有"**：第一回合必定入手且最先抽（不占固定抽牌数），但仍受手牌上限限制 —— 按你写的行为实现。
6. **药水槽位"显示在玩家 UI 上方"**：做成 HUD 上的独立一排（默认在生命值/物品栏上方），不占物品栏格子。
7. **事件上限（15/5/5/5）**：上限是**每层**独立计算，达到上限后该类别不可再触发；BOSS 战不受限且可随时发起。
8. **"下一场战斗开始时清空未领奖励"**：清空的是**上一战留下的待领卡牌奖励**（含三选一与金币已到手部分不回收）。
9. **火堆"不能连续进行多次"**：同一层内两次火堆之间必须发生至少一次其它事件（战斗/问号/精英），否则提示不可用。
10. **"影响范围控制不会过高"**：战斗冻结只作用于**本次遭遇战锁定的敌人**加上"开战时半径内被卷入的敌对生物"，
    不改变全局难度/刷怪；未参战的远处怪物不受影响（既不会被打，也不会被冻结）。
11. **LICENSE**：按你给的措辞添加 `LICENSE.txt`（"版权所有。请参见 LICENSE.txt。"），并在 `neoforge.mods.toml`
    的 license 字段改为引用该文件。
12. **（V9）独立生命值的上限**：用配置 `maxPlayerHp`（默认 75），**不再用角色表里的 `maxHp`**；
    角色表的最大生命现在只设置原版血条（那已经与战斗无关）。开新局（首次选角色/切到没开过的新角色）时补满。
13. **（V9）事件计数的时机**：一次战斗在**开战时**计数（打完/中途放弃都不退），
    这样可以避免"反复开战刷事件"；达到上限后开战会被直接拒绝并提示去挑战 BOSS。
14. **（V9）多人各自的进度**：能否开战以**发起者**的进度为准，参战者各自的计数与 BOSS 击杀**各自记录**
    （与 §4 的"每人独立计数与奖励"一致）；队友自己的该类事件已达上限时，本场对他不计入。
15. **（V9）找不到 BOSS 就不给打**：`bossChallengeRadius`（默认 64 格）内必须真的存在该层的 BOSS 实体
    （监守者 / 凋零 / 末影龙），本 mod **不生成** BOSS；这样既满足"需自行寻找"，也能随时直挑 BOSS。

## 8. V2 完成证据

实现：`MobCombatant.syncIntentLabel()` / `clearIntentLabel()`（把意图写成头顶文字）、
`CombatContext.previewDamage()`（公开的伤害预览，`dealDamage` 改走它，保证预览与结算永远一致）、
`CombatManager.refreshIntentLabels()`（每次开局/出牌/结束回合刷新，敌人倒下顺手清名字）、
配置项 `showEnemyIntentAboveHead`。

* **用原版名称牌渲染，而不是自绘世界文字**：名称牌会自动面向镜头、贴合头顶高度，
  并且名字是实体数据、天然同步给所有客户端 —— 多人下每个人看到同一份意图，也不用处理投影矩阵；
  战斗结束时把名字还原（`setCustomName(null)`）
* 文字示例：`僵尸：攻击 5（将对 玩家A 造成 5 点伤害）`、`骷髅：攻击 4×2（将对 玩家A 共造成 8 点伤害）`、
  `史莱姆：防御 6（将获得 6 点格挡）`；显示的是**实际**伤害（力量/虚弱/易伤都算进去）
* 引擎自检新增 6 项伤害预览校验（力量 +2 → 8、虚弱 → 6、易伤 → 9、不为负、**预览值与实际掉血一致**）：
  整套自检 **74/74 通过**
* 编译通过；`runData` 运行期无异常

**仍需游戏内验收**：文字是否真的出现在头顶、字号与位置是否可读、多人下是否一致。
注意：战斗期间敌人的**原名会被意图文字替换**（形如 `僵尸：攻击 5（…）`），战斗结束还原。

## 9. V3 完成证据

实现：`combat/core/StandoffLayout`（**零 MC 依赖**的站位几何：方向、距离、多人散开、朝向）、
`combat/mc/PlacementHelper`（安全落点搜索 + 传送 + 转向）、`CombatManager` 的 `positionParty` /
`lockBystanders` / `unlockBystanders` / `allowEngineLethal`、`CombatEvents` 的伤害拦截、
`client/StcClientSetup` 的第三人称切换、6 个新配置项。

* **面对面站位**：以敌人重心为基准，沿"重心 → 玩家原位"方向退到 `battleStandoffDistance`（**≥5 格**，低于 5 会被抬到 5），
  多人沿垂直方向各偏 1.6 格避免叠在一起，并转向敌人重心
* **找不到安全落点就不传送**：`PlacementHelper` 会找"脚下实心 + 头顶两格空 + 无流体"的落脚点
  （地表上下各 4 格），找不到时只把玩家转向敌人，**绝不把玩家塞进墙里/岩浆**
* **冻结范围受控**：只针对敌对生物（`monster.Enemy`），玩家/被动生物/宠物完全不受影响；
  半径取 `freezeRadius`（0 = 跟随 `combatRadius`）且**上限 24 格**；已属于其它遭遇战的怪物不会重复冻结
* **免伤**：战斗期间参战玩家免疫**一切外来伤害**（摔落、岩浆、其他怪、其他玩家……），
  同时保留了"引擎自己的处决伤害"专用通道（`allowEngineLethal`），否则玩家永远不会倒下；
  引擎结算走 `setHp` 不经过 `hurt`，所以拦下 `hurt` 不影响战斗数值
* **第三人称**：客户端在战斗期间自动切到第三人称背面视角，战斗结束**恢复玩家原来的视角设置**
* 引擎自检新增 12 项站位几何校验（距离下限、方位、朝向约定四个方向、多人不重叠、重心重合兜底）：
  整套自检 **86/86 通过**；全部 7 套自检合计 **213 项**通过；编译通过；`runData` 无异常

**仍需游戏内验收**：站位观感（会不会把人摆到奇怪的地方）、第三人称是否顺眼、
附近怪是否真的不动手、局外伤害（摔落/岩浆/别的怪）是否被拦下、战斗结束后一切是否复原。

### 8. 战斗奖励根本触发不了（创造模式尤其明显）

**根因**：战斗内怪物是被引擎处决的 —— `killMob` 走 `mob.kill()`（无来源伤害），
原版 `getKillCredit()` 是空的，所以 `KillTracker` 从来数不到战斗击杀，**永远凑不满阈值、也就从来没有奖励**。
创造模式下玩家又几乎不会用剑补刀，于是表现成"完全触发不了"。

**处理（按反馈给的思路）**：

* **每场胜利必给一次奖励**：新增配置 `rewardPerVictory`（默认开），胜利后按本场档位发金币
  （普通 16 / 精英 40 / BOSS 60）与一次三选一（BOSS 必出金色）。
* **奖励入口改成"战斗结束立刻弹"**：`concludeIfOver` → `release` → `RewardService.openPendingRewards`，
  不再需要回收纳包点「领取奖励」。
* **收纳包里的领奖入口已移除**：`CardBinderMenu.BUTTON_CLAIM_REWARD` 删除，
  主页只剩三个模块 + 一行奖励状态；`/stc reward open` 保留给管理员调试。
* **击杀记账补全**：`Combatant.recordDamageFrom(Combatant)` 钩子（引擎在 `dealDamage` 里调用），
  `MobCombatant` 记住"最后打它的玩家"，处决时由 `CombatManager.creditKill` 直接调用
  `RewardService.recordCombatKill` 记账；引擎击杀会在 `ENGINE_KILLS` 里登记一笔，
  `KillTracker` 跳过它们，**原版击杀路径与战斗击杀路径不会重复计数**。
* **同种类击杀累计**（原设计）保留为额外奖励，阈值从 10/4/1 降到 **5/3/1** 便于测试；
  每次击杀都会在聊天栏显示「击杀进度：zombie 3/5（普通档）」，让玩家看得见在计数。
* **待领期间不受攻击**（反馈要求）：`CombatEvents.onIncomingDamage` 在 `pendingRewards() > 0` 时同样取消伤害；
  `onPlayerTickReward` 每 3 秒检查一次，玩家没开着别的容器时**自动把三选一界面再弹出来**；
  `CombatManager.startPreconditions` 在还有待领奖励时**拒绝开战**（免得 V9 的"下一战作废"把奖励吞掉）。

### 9. 独立生命值不应该和玩家生命值关联

**处理**：

* `PlayerCombatant.onHpChanged` / `onDefeated` 现在**什么都不做**（以前 `onHpChanged` 会写原版血条、
  `onDefeated` 会通过原版伤害把玩家打死）。
* 删除配置 `defeatKillsPlayer` 与整套 `ENGINE_LETHAL` 放行机制（没有原版处决就不需要它了）。
* `CharacterSelection` 不再改 `MAX_HEALTH` 属性、也不再把原版血量补满；**本 mod 不再写玩家原版血量**。
* 独立生命值归零 = **本局结束**（`ProgressState.defeated`）：可以在尖塔入口换角色或用「重开本局」，
  按 `resetHpOnDefeat` 回满或保留 1 点；原版角色、物品、经验完全不受影响。
