**生成牌『小刀』（`shiv`）**：0 费攻击，造成 4 点伤害、消耗（强化版 6 点）。
注册方式很重要，见下面的坑。

### 这批补掉的 3 个引擎缺口

| # | 原语 | 说明 |
| --- | --- | --- |
| **E10** | 小刀 `shiv`（生成牌）+ `Combatant.shivBonus` | `registerGenerated` 登记"不进奖励池"的牌；精准给玩家加 `shivBonus` |
| **E13** | `CombatContext.moveHandToDrawPileTop(owner, index)` + `CardPickKind.PUT_ON_TOP` | 战吼用；同时把布置 `setup` 的路也铺好了 |
| **E12** | `CombatContext.playTopOfDrawPile(owner)` | 浩劫用：**不花能量**地打出抽牌堆顶那张（需指定敌人的牌随机挑目标），照抄 `playCardFor` 的那套记账（附魔作用域 / 活力 / 出手格挡特效 / "每打出一张牌"钩子），打完进消耗堆 |

### ⚠️ 两个踩到的坑（都写进注释了）

1. **`registerGenerated(base, upgraded)` 不能用于"同 id 的一对"**：它把两者都塞进 `BY_ID` 的同一个键上，
   后者覆盖前者 → 基础版没了、`UPGRADED` 里也没有 → 被"每张非状态牌都要有强化版"那条自检当场抓住。
   正确写法：基础版 `registerGenerated(...)`，强化版 `upgrade(...)`（两者同 id，
   `isGenerated("shiv")` 按 id 判断，照样成立）。
2. **战吼的强化是"抽 2 张"、消耗保留** —— 我凭印象原以为是"去掉消耗"。第三次被 kamigame 卡页纠正。

### ⚠️ 两个刻意的取舍（都写进注释了）

1. **【布置】的免费是"按 id 计数"的近似**：本引擎的 `Card` 是**不可变共享定义**、没有"卡牌实例"
   （见 §3 的 E5）。所以手里有两张同名牌时，先打出的那一张免费。实战里【布置】把它放到**抽牌堆顶**，
   下一张抽到的就是它，顺序上不会产生歧义。
2. **【火焰屏障】的"本回合"跨到了敌人回合**：模组的"回合"是"玩家回合 + 敌怪回合"一轮，
   所以临时荆棘活过敌怪回合、在自己下一个回合开始时收回（这正是原版语义）。

自检：引擎裸 JVM **1609 → 1658**（+49，其中 A4-12 相关 48 条）+ MC 套件 1669 → **1675**
（`BattleViewCheck` 133 → 139：钩子接线与 `effectiveCost` 的源码级断言）。

### ⚠️ 双发的三个取舍

1. **目标死了就随机换一个**（第二遍开始时如果原目标已倒下），与原版"牌还在、只是目标没了"一致。
2. **第二遍遇到选牌会略过**：选牌只有一个槽位，第二遍的 `beginCardPick` 会覆盖第一遍的快照，
   第一次的选择就凭空消失。所以宁可少打一遍 —— 自检里用【战吼】（先抽牌再挂选牌）钉住了这个行为。
3. `cardsPlayedThisTurn`（【突出重围】用）**只 +1**，但出牌钩子（千刀万剐 / 余像 / 遗物"打出卡牌后"）
   会触发**两次** —— 因为"打两遍"对后者就是两次出牌。

自检：引擎裸 JVM **1658 → 1699**（+41）+ MC 套件 1675 → **1681**（`BattleViewCheck` 139 → 145：
格挡单入口 / 涂毒旗标 / 腐化费用 / 双发循环 / 选牌保护的源码级断言）。**合计 3380 项全通过**。

## 4. 已知取舍 / 需要用户拍板

1. **卡名是我按官方中文译名写的**（`slice`=切片、`deflect`=偏斜、`bane`=剧毒、`disarm`=卸甲、
   `hemokinesis`=血液动力学…）。如果你有惯用的叫法，告诉我改名就行 —— 改名只动 `CardLibrary` 里那一个字符串。
   * 例外：**`prepared` 我译成「准备」**（原版中文译名也是"准备"），但注意它和"战吼"这类"抽牌 + 塞牌"的
     牌容易混，卡面文案都写清楚了。
2. **【致命毒药】已经是稀有牌**（12 层中毒，v0.5.1.5 从"金色"统一成稀有），
   而原版它是常见的 5 层中毒。我**没有动它**，也没有再加一张同名卡 —— 要不要按原版降成常见牌由你定。
3. **【撞击】的卡面数字**：伤害等于当前格挡值，文案里没有固定数字，我让卡面在括号里补了
   "（当前 N 点）"（`CardPreview.liveDescription`）。v0.5.2.0 唯一碰表现层的地方。
4. **数值一律取原版基础值**；跟本 mod 已有的状态体系（虚弱 = 每层 -1 伤害、易伤 = 层数
   **且只有 +25%**、敏捷 / 力量与虚弱互相抵消）联动时以本 mod 的规则为准。几个因此"看起来不一样"的点：
   * 【恐惧】给 99 层易伤 —— 本 mod 易伤每回合 -1 层，所以 99 层 = 本场永久（与原版意图一致），
     但**增伤是 +25% 而不是原版的 +50%**（这是本 mod 全局限定，不是这张牌的问题）。
   * 【飞踢 / 脚后跟钩】的条件奖励，条件是**按目标身上的易伤 / 虚弱层数**判定的，与原版一致。
   * 【不适】先减力量再叠虚弱，两者在本 mod 会互相抵消 —— 所以"力量被虚弱再抵掉几层"是正常结果。
5. **没有做美术**：新卡沿用程序化卡面（`CardArt` 找不到 `<id>.png` 时的兜底），
   想换真图就往 `assets/stc/textures/card/<id>.png` 丢一张。
6. **新加的 113 张卡都没有目视验证**：卡面排版（长卡名如「死吧死吧死吧」「血液动力学」会不会顶出框）、
   图鉴里的排序、奖励池出货率都要你上手看。
7. **【逃生计划】的一个边界**：判定用的是"抽完之后手牌里最后一张"。手牌已满时那张牌直接进弃牌堆、
   不算抽到，也就不给格挡（与原版"抽到的是技能牌"的语义一致）。
