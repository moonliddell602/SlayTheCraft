# SlayTheCraft

# 这是什么？
SlayTheCraft，方块尖塔，旨在把《杀戮尖塔》式的**回合制Rouge卡牌战斗**搬进 Minecraft 的 NeoForge 模组。

你在一张战场上用手牌打敌人，敌人头顶的UI预告它们下一步要干什么；打赢三层的 BOSS 就算单局的通关。

卡牌、遗物、药水、进度都挂在**玩家档案**上，不占用你的原版血量与物品栏。

```
Minecraft 1.21.1  ·  NeoForge 21.1.251  ·  Java 21
mod id: stc      mod 名称: SlayTheCraft      当前版本: 0.5.5.3
```

## 装起来

1. 装 **Minecraft 1.21.1** + **NeoForge 21.1.251 或更高**；
2. 把 `dist/stc-<版本>.jar` 丢进实例的 `mods/` 文件夹；
3. 起游戏。

**可选前置**（缺了会自动降级，不会崩）：

| 模组 | 装了会怎样 | 没装会怎样 |
| --- | --- | --- |
| **Curios** | 收纳包可以放进饰品槽 | 降级成"主手 / 副手 / 背包"携带判定 |
| **FTB Teams** | 多人按 FTB 队伍判定队友 | 降级成原版 `/team` |

> **本模组对原版改动的范围**（除此之外不动原版）：
> 
> ① 战斗进行中**隐藏原版 HUD**。
> 
> ② 村民获得**本模组自己的职业**【卡牌大师】时，右键它打开的是模组商店而不是原版交易面板
> （其他村民职业的原版交易完全不受影响）；
> 
> ③ 尖塔内容全部由模组自己的方块、物品与快捷键主动触发。

## 上手：五分钟打第一场

```
1. 创造模式：物品栏 → 找到「杀戮尖塔：战斗」标签 → 拿【尖塔入口】和【卡牌收纳包】
生存模式：通过合成获得【尖塔入口】和【卡牌收纳包】
2. 放下【尖塔入口】，空手右键 → 选一个角色（点角色卡看详情 → 「选择这个角色」）
3. 把【卡牌收纳包】拿在主手或副手，然后用【战斗军旗】右键敌人开战
4. 屏幕底部出现手牌 → 点牌出牌（需要目标的牌再点敌人）→ 点「结束回合」
5. 打光敌人 → 胜利并弹出三选一奖励

```

> 第一次玩也可以在【尖塔入口】点 **「新手教程」**：分五章讲怎么上手、战斗机制、尖塔旅行、
> 收纳包用法与图鉴/奖励（内容随游戏语言切换）。

> 开战只有一条路：**用【战斗军旗】右键附近的敌人**。
> 尖塔入口里的「开始对战」按钮已在 v0.5.0.13 移除，
> 而军旗这条路一直是有效的。

快捷键：**B** 打开卡牌收纳包（界面内可改键），**R** 结束回合，**1–9** 快速出对应的手牌。

## 战斗规则

### 一个回合的顺序

```
你的回合开始
  ├─ 能量刷新（默认 3 点）
  ├─ 清空自己的格挡
  ├─ 状态结算（再生回血、灼烧 / 凋零掉血、力量药水到期…）
  ├─ 抽牌到 5 张（手牌上限 10，超出直接进弃牌堆）
  └─ 充能球被动触发
出牌环节（打牌 / 用药水 / 查看牌堆）
  ├─ 结束时：【中毒】按层数造成伤害
  ├─ 结束时：手牌里的状态牌 / 诅咒牌结算（灼烧·毒液 4 点伤害、呼唤失去 5 生命、残忍失去手牌数的生命…）
  └─ 结束时：【神龟】给格挡
敌人回合
  ├─ 清空敌人格挡
  ├─ 敌人**一只一只**行动（画面从左到右，每只间隔 1.2 秒）
  ├─ 敌人自身状态衰减
  └─ 预告它们下一回合的意图
```

多人时顺序是 `玩家1 → 玩家2 → … → 敌人 → 下一轮`；不是你的回合时点牌会被拒绝并提示轮到谁。

### 伤害怎么算

| 概念 | 规则 |
| --- | --- |
| **格挡** | 受击时先扣格挡，溢出部分才掉 HP；每回合开始时清空自己的格挡 |
| **造成伤害** | 敌人攻击与卡牌伤害走这条，**可被格挡抵消** |
| **失去生命值** | 灼烧 / 凋零 / 中毒处决与部分状态牌走这条，**无视格挡、直接扣血** |
| **力量** | 每层 +1 攻击伤害 |
| **虚弱** | 层数 = 剩余回合数，期间**攻击伤害 −25%**（不随层数叠加） |
| **易伤** | 层数 = 剩余回合数，期间**受到伤害 +25%** |
| **迅捷 / 缓慢** | 每层让获得的格挡 +1 / −1（最低 0） |
| **活力** | 下一张**攻击牌**额外造成等于层数的伤害，打完清零（打技能牌不消耗） |

虚弱与易伤同时存在时先算虚弱再算易伤（`floor(floor(基础 × 0.75) × 1.25)`）。

### 胜负与倒下

| 情况 | 结果 |
| --- | --- |
| 敌人全灭 | 胜利，解锁敌人，发奖励 |
| 你的独立生命值归零（单人） | **按原版流程死亡**，重生后回到第 1 层、清空角色、金币重置 |
| 多人时你倒下但队友还活着 | 在局内等待（回合被跳过），队友打赢后恢复 1 点生命值 |
| 多人全员倒下 | 所有人一起被击杀并各自重开 |
| 点「放弃战斗」 | 二次确认（红框高亮）后**直接死亡** |

战斗期间**附近生物被冻结**（不追不打），你也不会受到**外来伤害**（摔落、岩浆、别的怪）；
引擎的处决伤害走专用通道，不会被免伤挡掉。

## 遗物

**共 24 件**。遗物是永久被动，触发点有 6 个：战斗开始 / 回合开始 / 回合结束 /
打出卡牌后 / 战斗胜利 / 本场战斗首次失去生命。

遗物一共有**三条随机通道**：战斗掉落、藏宝箱、商店 —— 每件遗物只走其中一部分，见下表。

| 来源 | 说明 |
| --- | --- |
| **初始遗物** | 4 件，**角色专属**：只在对应角色开局时发放，战斗掉落 / 藏宝箱 / 事件 / 指令都拿不到 |
| **战斗掉落（精英与 BOSS）** | 含精英或 BOSS 的战斗胜利后，每名参与者各必得一件随机未拥有的遗物 |
| **常规战斗掉落** | **10%** 概率掉一件**非特殊**遗物（"只能商店"与"藏宝箱 / 商店"那几件不掉）；概率由配置 `normalBattleRelicChance` 控制 |
| **藏宝箱** | 副手【卡牌收纳包】+ 主手**任意镐**右键**陷阱箱**，开出一件随机遗物（不能连开两个；"只能商店"的【龙蛋】不在池里） |
| **商店** | 卡牌大师商店的 3 个遗物位，**逐件定价 195~240 金币**（v0.5.3.1 之前是统一价 150）；现在商店里能出现的 14 件**全部有单价** |
| **事件专属** | 6 件（袭击号角 / 失活的珊瑚 / 海洋之心 / 嚒咕菲力 / 蜂蜜佐料 / 受惊的小猪仔）**只在对应事件里出**，不进任何随机途径 |
| **只能商店** | 【龙蛋】240 金币，只能从商店买（v0.5.3.2 起） |
| **藏宝箱 / 商店** | 【行商羊驼披肩】205、【制图台】210 —— 这两件**不进战斗掉落**（v0.5.3.1 / v0.5.3.2 先后从"只能商店"改过来） |

> 全表（含每件的售价与来源）见 [`docs/relics-export.md`](docs/relics-export.md)，由代码直接导出。

## 药水

**共 15 种**，独立槽位（默认 3 格，【药水腰带】遗物可 +2）。药水**只在战斗内显示**
（战斗外的物品栏上方不占位）。

* **正面药水**（治疗 / 力量 / 迅捷 / 神龟 / 再生 / 缓降 / 蘑菇煲…）点一下**直接对自己生效**；
* **负面药水**（中毒 / 火焰 / 虚弱 / 凋零…）点一下进入选目标模式，再点敌人释放；
* 贴图按用途区分：对敌人用的显示**喷溅**瓶、对自己用的显示**常规**瓶、
  特殊药水（不祥之瓶 / 幸运 / 奶桶）显示**滞留**瓶。

## 充能球（故障机器人）

**只有故障机器人有充能球栏位**（默认 3 个，其他角色是 0 个，界面上连空位都不显示）。

| 球 | 被动（回合结束触发） | 激发 |
| --- | --- | --- |
| **闪电球** | 对随机敌人 3 点伤害 | 8 点伤害 |
| **冰球** | 2 点格挡 | 5 点格挡 |
| **暗球** | 每回合充能 +6（初始 6） | 对**当前生命最低**的敌人造成等于充能的伤害 |
| **等离子球** | 回合开始 +1 能量 | +2 能量 |

* 栏位满了再获得新球会**先激发最前面那颗**；
* 世界里显示成**腰部环绕的小方块**（闪电=黄色蛙鸣灯、冰=蓝冰、暗=哭泣的黑曜石、
  等离子=品红染色玻璃、空位=标靶），**队首永远朝向敌人**，只在生成新球时转一格；
* **专注**会加成闪电球 / 冰球 / 暗球的被动与激发数值（**不影响等离子球**，与原版一致）。

## 状态与关键字

### 状态

| 状态 | 规则 |
| --- | --- |
| **灼烧** | 可累加；每累计一点，下回合开始时造成等量伤害（无视格挡） |
| **中毒** | 出牌环节结束时按层数造成伤害（可被格挡）；每个新回合 −1 层 |
| **凋零** | 可累加；**累计层数大于当前生命值**时，回合结束立刻死亡 |
| **再生** | 回合开始恢复等于层数的生命 |
| **缓降** | 免疫下一次受到的伤害（触发后 −1 层；只挡"伤害"，不挡"失去生命值"） |
| **神龟** | 结束出牌时获得等于层数的格挡 |
| **虚弱 / 易伤** | 见 [伤害怎么算](#伤害怎么算) |

#### 状态牌与诅咒牌

由敌人或事件塞进你的手牌 / 弃牌堆，**不进任何卡池**：

* **状态牌**：虚空（抽到费用 −1、打不出）、粘液（1 费抽 1、消耗）、灼烧（打不出、回合结束 4 点伤害）、
  晕眩（打不出、虚无）、毒液（1 费、回合结束 4 点伤害）、呼唤（1 费、回合结束失去 5 生命）、
  箭在弦上（0 费、获得活力 4）、不屈；
* **诅咒牌**：残忍（回合结束失去手牌数的生命）、贪婪（失去 10 金币）、
  戏谑（回合结束往弃牌堆复制一张）、固执（获得 2 层易伤）。

### 卡牌关键字

| 关键字 | 含义 |
| --- | --- |
| **保留** | 回合结束时不弃掉，留在手里 |
| **消耗** | 打出后进消耗堆，本场战斗不会再抽到 |
| **虚无** | 回合结束时若还在手里，直接被消耗 |
| **固有** | 开局就在手牌里 |
| **能力** | 打出后效果常驻，这张牌本场从牌组里消失 |

## 进度、层级与奖励

### 独立生命值

生命值属于**玩家档案**，与**原版血条完全解耦**：

* 上限由角色决定（默认 75 那一档，见 [角色](#角色)），跨战斗保留；
* 受原版伤害**不会**掉独立生命值，独立生命值归零**会**让原版角色死亡；
* 打赢任意一场 BOSS 战 → **参战所有人立刻回满**。

### 三层进度

| 层 | 目标 BOSS（找到任意一只即可挑战） | 尖塔战斗生命 |
| ---: | --- | ---: |
| 1 | 旋风人 / 唤魔者 / 嗅探兽 | 224 |
| 2 | 僵尸疣猪兽 / 熊猫 / 远古守卫者 | 415（远古守卫者 320） |
| 3 | 末影龙 / 凋零 / 坚守者 | 675（末影龙用原版血量） |

* BOSS **不生成**，需要你自己去找；击败本层任意一只 BOSS 就进下一层；
* **所有 BOSS 只能打赢一次**，进下一层后上一层 BOSS 就打不到了；
* 本层有**事件上限**：常规战斗 15 / 精英 5 / 火堆 5 / 问号 5；
* 每层有**专属怪物池**——非本层的怪根本不会触发战斗（例如第 1 层只能遇到亡灵与常规生物）。

### 多人加成

每多一名组队玩家，敌人的战斗生命 **+50%**（2 人 ×1.5、3 人 ×2.0、4 人 ×2.5，开战时聊天栏会写明倍率）。
同一队玩家一起进入**同一场遭遇战**，最多 4 人；敌人共享，
**每人各自拥有能量 / 手牌 / 抽牌堆 / 弃牌堆 / 格挡**。

## 事件与篝火

| 类型 | 怎么触发 | 效果 |
| --- | --- | --- |
| **篝火** | **副手**拿【卡牌收纳包】+ **主手**拿【打火石】→ 右键点燃的营火 | 打开准备界面：愈合 25% / 锻造（强化一张卡）/ 多人包扎 |

  同一层的同一个事件**只能访问一次**（进下一层后刷新）；

## 指令一览

所有指令以 `/stc` 开头，回执默认**保留在聊天栏**（战报与系统提示默认静音，见配置 `chatOutput`）。

```
/stc combat   start [半径] | status | play <手牌> [敌人] | end | quit | selftest | help
/stc binder   status | give | gold <数量> | add-card <卡牌> [数量] | remove-card <卡牌>
              upgrade [卡牌] | enchant <卡牌> <附魔> | clear
/stc reward   status | grant [true] | open | clear
/stc relic    list | grant [id] | clear
/stc potion   list | give <id> | clear
/stc status   [add <状态> <层数> [敌人]] | card <id> [数量] | clear
/stc progress [show] | heal [n] | damage <n> | boss | floor <1-3> | reset | campfire
              | restart | endrun | selftest
/stc villager cardmaster
```

> `progress boss` = 直接记录"本层 BOSS 已被击败"（进阶 / 通关）；
> `progress endrun` = 模拟战败结束本局；`progress restart` = 重开本局。

## 给整合包作者与附属包：接口

`com.slaythecraft.api.StcApi`：

| 方法 | 作用 |
| --- | --- |
| `registerCardTexture(卡牌 id, 贴图位置)` | 指定卡面插画（也支持零代码的约定路径，见素材工作区） |
| `registerBossMusic(层号, 声音事件 id)` | 给某层绑定 BOSS 音乐（也有零代码约定，见下） |
| `registerBinderBackground / Buttons / Avatar / DefaultAvatar` | 收纳包系列界面的皮肤，传 `null` 撤销 |
| `bossMusicConvention(层号)` | 返回约定的事件名 `stc:boss_music_floor_<层>` |

**附属包加角色**：在 `FMLCommonSetupEvent`（或更早）调用

```java
CharacterRegistry.register(new CharacterProfile(myId, hp, energy, deck, relicId, orbSlots, ""));
```

两条纪律：**列表被读过之后不能再注册**（会冻结），**id 必须唯一**——违反会被拒绝并记警告，
这样能避免"游戏中途多出一个角色导致索引与存档错位"。

**数据包**：怪物档位在 `data/stc/tags/entity_type/mob_tier/{elite,boss}.json`，整合包可直接改。

## 素材工作区

| 目录 | 作用 | 进 jar？ |
| --- | --- | --- |
| **`assets/`**（项目根目录） | **素材工作区**：放卡牌插画 / 贴图 / 模型 / 音乐 / 音效 / 字体，放 PSD、`.bbmodel` 也无所谓 | ❌ |

```powershell
.\tools\import-assets.ps1          # dry-run：预览会复制什么
.\tools\import-assets.ps1 -Apply   # 真的复制进打包目录
```

已经接通的位置：

| 素材 | 现状 |
| --- | --- |
| **卡牌插画** | ✅ 按卡牌 id 命名（`strike.png`）放进 `textures/card/` 即可，出现在手牌 / 详情页 / 图鉴 / 牌堆 |
| **BOSS 音乐** | ✅ 放 `sounds/boss/floor_<层>/floor_<层>.ogg` **就生效**，不用写代码（1–3 层已随包发布） |

| **状态 / 充能球图标** | ⚠️ 现在复用原版状态效果图标 |
| **音效 / 字体** | ⚠️ 告诉我用在哪即可 |

`sounds.json` 必须在 `assets/stc/` 根目录。

## 代码结构

```
src/main/java/com/slaythecraft/
├── combat/core/          ★ 纯 Java 战斗引擎，零 Minecraft 依赖（51 个类）
│   ├── CombatContext          回合状态机与伤害结算（引擎本体）
│   ├── CardLibrary            全部卡牌定义 + 强化版（123 张）
│   ├── RelicLibrary / PotionLibrary / StatusCards / Orb
│   ├── MobIntents / FloorBoss / FloorPools / Faction
│   └── CombatSelfTest         引擎自检
├── combat/mc/            Minecraft 接入层（战斗管理器、意图、档位、事件与指令）
├── character/            角色注册表、初始牌组与初始遗物
├── data/                 玩家档案（卡牌 / 金币 / 生命 / 进度 / 遗物 / 药水）+ Attachment
├── binder/               卡牌收纳包物品、界面菜单、删卡服务、Curios 兼容
├── achievement/          原版进度（成就树）的登记、授予与诊断
├── gate/ merchant/ campfire/ question/ villager/ station/
│                         尖塔入口、卡牌大师商店、篝火、问号事件、村民职业
├── reward/ potion/ relic/ progress/ team/
│                         奖励抽取、药水、遗物、层级进度、队伍判定
├── network/              网络包与战斗快照编解码
├── client/               仅客户端加载（界面、渲染、动画、按键）
└── api/                  给整合包与附属包的公开接口
```

**设计要点：规则与 Minecraft 完全解耦。** `combat/core` 只依赖 JDK，
所以同一套规则既能驱动游戏内战斗，也能在没有 Minecraft 的普通 JVM 里跑自检——
这也是这个项目每一批改动都敢直接跑全量验证的原因。

## 构建与自检

### 构建

本机 PATH 上的 `java.exe` 是坏的，跑 Gradle 前显式指定 JDK：

```powershell
$env:JAVA_HOME = "D:\itheima\environments\openjdk21"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\gradlew.bat build --offline --console=plain
```

产物在 `build\libs\stc-<版本>.jar`（本仓库同时会在 `dist\` 留一份）。
版本号改 `gradle.properties` 的 `mod_version`。

### 一键自检

```powershell
powershell -ExecutionPolicy Bypass -File tools\run-checks.ps1
```

**当前基线：3818 项全通过**（引擎裸 JVM 1981 项 + MC 类路径 23 套 1837 项）。
引擎自检能单独跑（不需要 Minecraft 类路径）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\run-checks.ps1 -EngineOnly
powershell -ExecutionPolicy Bypass -File tools\run-checks.ps1 -Only Advancement   # 只跑名字含 Advancement 的套件
```

游戏内等价入口是 `/stc combat selftest`。

> 脚本刻意写成**纯 ASCII**、靠**退出码**判定成败：它曾经带中文，而 Windows PowerShell 5.1
> 会把丢失 BOM 的 UTF-8 当 GBK 读，整个脚本变乱码。请用 `powershell` 而不是 `pwsh` 跑它。

## 已知未接线与偏差

这些地方**没做完**，别当成已实现：

* ✅ **A4 补卡已完成**：铁甲战士 **73/73**、静默猎手 **73/73**（v0.5.2.0 ~ v0.5.4.1，共 118 张角色牌）；
* **【行业工具】的弃牌 / 【计划周全】的保留**本是"玩家自己选"，当前按贪心自动决定（详见 `docs/handover.md` §6）；
* **【尸体爆炸】的爆炸伤害**走固定伤害（会被格挡吸收，不受力量 / 虚弱 / 易伤放大）；
* **【灼热打击】的档位定义懒生成**，图鉴 / 合成表 / 奖励池里只出现基础版一张；
* **闪光弹**（v0.5.5.2 按用户原文）：0 费 · 无色 · 技能 · **保留 + 消耗** · 只击晕；**闪光弹+** 的
  "击晕 + 2 层易伤"仍是我补的升级收益（等权威数值）；
* **【商队护送】单人（队伍 1 人）不进奖励池、商店也不上架**，多人（≥2 人）两边都会出现
  （v0.5.5.2 奖励池 / v0.5.5.3 商店）；
* **「循环」** 触发的是**所有**充能球的被动（本引擎没有"只触发单颗球被动"的接口，
  1 颗球时与原版一致，多颗时更强）；
* **闪光弹+** 的升级效果（击晕 + 2 层易伤）是补的，原始需求只给了基础版；
* **卡牌定义仍在代码里**（`CardLibrary`），数据包注册表 `stc:card` 是**覆盖层**（v0.5.5.0，A6-1）：
  数据包能新增卡 / 改内置卡数值，但目前**只有 10 张内置卡以 JSON 镜像在注册表里**，
  其余仍是纯代码定义；数据包也只能组合**行为表里已有的 19 条行为**（造新机制要改代码）。
  详见 [`docs/card-registry.md`](docs/card-registry.md)；
* **遗物是无状态的**（只有 6 个触发点，"每打出 3 张牌抽 1 张"这类还没做）；
* **界面与卡面是程序化占位样式**；**美术素材（卡图 / 遗物图）由使用者自行提供**，不在开发待办里。
  通道已经做好（v0.5.5.1）：把图片按 id 命名丢进 `assets/cards/`，再跑
  `powershell -ExecutionPolicy Bypass -File tools\import-card-art.ps1 -Import`
  —— 它会批量复制进资源路径并报告还缺哪些；246 张的 id 清单见 `assets/cards/card-art-checklist.md`。
  素材到位后重新 build 即可，**不需要改代码**（详见 `assets/cards/README.md`）。
* **表现层的手感参数**（动画时长、手牌位置等）没有经过目视验证。
